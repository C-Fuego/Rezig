# zmatrix

`cmatrix` 的 Zig 复刻：列式字符雨、白色头部、半角片假名、异步滚动、屏保模式、
彩虹、旧式滚动、运行时按键。零第三方依赖，只用 `std` 与 `std.os.linux`，
在 **Zig 0.17.0 / 0.18.0-dev.935** 上编译通过。

渲染是 `cmatrix.c` 的逐条移植（真实格子数组，不是哈希伪造的字符），所以
字符集、列密度、颜色档位、下落与旧式滚动都能和原版对齐。

## 构建 / 运行 / 测试

```sh
zig build                              # 产物: zig-out/bin/zmatrix (~277 KB)
zig build -Doptimize=ReleaseFast
./zig-out/bin/zmatrix -h
zig build test                         # 39 个单元测试

./zig-out/bin/zmatrix -C blue -a
./zig-out/bin/zmatrix -c -u 2 -r
./zig-out/bin/zmatrix -s -M "wake up, neo"
```

## 渲染模型（与 cmatrix.c 对应）

- **列**：原版 `for (j = 0; j <= COLS-1; j += 2)`，因此只有**偶数列**下雨，
  奇数列永远空着。逻辑列数 = `ceil(终端列数 / 2)`；80 列终端 = 40 根雨柱。
- **格子状态**：每列 `rows + 1` 个格子（`val[]` + `is_head[]`），索引 0 在
  屏幕上方一行之外，索引增大 = 更靠下 —— 和原版 `matrix[i][j]` 完全一致。
- **新式滚动**：扫描每列，跳过空格段；对每个连续字符段在**下端**补一个新字符
  并标记为头部；段长超过 `length` 时把上端抹成空格。新雨柱总是从屏幕第 0 行
  开始生长，因为起始状态整屏为空（原版 `var_init`）。
- **旧式滚动 `-o`**：整列下移一格再把顶端填上，`val == 0` 的头部渲染成白色
  `&`，紧随其后的 `val == 1` 渲染成矩阵色 `|`，其余为随机字符 —— 于是形成
  原版那种实心雨柱。
- **头部**：`val == 0` 或 `is_head` 的格子用白色（SGR 37），加粗由 `-b/-B/-n`
  决定。头部永远是本列雨柱的**最下面一格**。
- **速度**：`-u` 每帧 `delay * 10 ms`；`-a` 时全局 `count` 在 1..4 循环，
  每列只在 `count > updates[j]`（`updates` ∈ 1..3）时推进，因此三档速度为
  3:2:1，和原版相同。
- **帧差分**：整帧只有启动/改尺寸时一次 `\e[2J`；之后每帧只写**变化的格子**，
  一行没变就一个字节都不发。首帧（屏幕状态未知）才整屏覆盖写、每行一直写到
  终端右边界。详见下面的「帧差分」。
- **属性不泄漏**：每次 SGR 都补齐「粗体开/关 + 前色」，从头部切到拖尾时显式
  发 `\e[22;3Xm`，因此拖尾不会继承头部的粗体。
- **不画背景**：输出里没有 `40-47` / `48;` / `100-107`，只有前色 SGR。
  详见「与 cmatrix 2.0 的差异」。

## 颜色

- **默认路径 = cmatrix**：只有 8 种 ANSI 前色（SGR 30-37），头部白色 37、
  拖尾矩阵色。没有 256 色，也不做 `TERM` 探测，所以任何终端上观感都和原版一致。
- **粗体四档**（完整复刻原版那个 `int bold`）：

| 档位 | 参数 | 头部 | 拖尾 |
| --- | --- | --- | --- |
| `none` | 默认 | 白 | 矩阵色 |
| `head` | `-n` | 白 + 加粗 | 矩阵色 |
| `dither` | `-b` | 白 + 加粗 | 隔字加粗（`val % 2 == 0`） |
| `all` | `-B` | 白 + 加粗 | 全加粗 |

  注意 `-n` 在原版里是「不加粗」，但它把 `bold` 设成 `-1`，而头部用的是
  `if (bold)`，所以 `-1` 为真 → **头部反而加粗**。这里照原版行为实现。
- **`-C black` 会几乎全黑**：原版 `init_pair(COLOR_BLACK, -1, -1)` 在
  `use_default_colors()` 之后会失败（pair 0 已被占用），于是黑色格子变成
  「黑底黑字」。这里只发 `\e[30m`（不改背景），观感同样接近不可见。
- **彩虹**：原版每格每帧 `rand() % 6`，集合是 绿/蓝/黑/黄/青/洋红（没有红，
  也没有白），所以 1/6 的格子是黑的；头部在彩虹模式下不再是白色（`val == 0`
  除外）。这里完全照做。
- **`--fade`（扩展，非 cmatrix）**：打开后拖尾按「到头部距离 / 本段长度」
  等比映射到 5 档 256 色（绿 `46→40→34→28→22`），头部亮白 97。`-o` 时关闭。
  16 色终端只有加粗/不加粗两档亮度，此时退化成 2 档。

## 终端处理

- stdin 是 tty：`tcgetattr`/`tcsetattr` 进 raw 模式（关 ICANON/ECHO/ISIG/IEXTEN，
  `MIN=1,TIME=0`，`OPOST` 关），退出时用保存的 termios 恢复。
- stdout 是 tty：`\e[?1049h` 进 alternate screen、`\e[?25l` 隐藏光标；退出时
  反向恢复并 `\e[0m`（和原版 ncurses 的 `smcup`/`rmcup` 等价）。
- `SIGWINCH`：只置原子标志，主循环下一轮 `ioctl(TIOCGWINSZ)` 重新分配列数组、
  重新 `var_init` 并清屏 —— 对应原版 `resize_screen()`。
- `SIGINT/SIGTERM/SIGQUIT/SIGHUP`：置退出标志 → 跳出主循环 → defer 恢复终端 →
  正常退出（`timeout --preserve-status` 得到 0 而不是 143）。
- `SIGPIPE` 忽略：下游（如 `| head`）关闭时 `write` 报错退出，不是被信号打死。
- fd 校验用 `ioctl(TCGETS)` 而不是 `std.posix.tcgetattr`：后者把 `EBADF`
  当作 `unreachable`，`zmatrix 0<&-` 会直接 panic。
- **尺寸**：`ioctl(stdout)` → `ioctl(/dev/tty)` → `$COLUMNS`/`$LINES` → 80×24，
  取第一个有效值。stdout 是管道时第 1 步失败，第 2 步从控制终端拿到真实尺寸，
  所以 `zmatrix | zlolcat` 也按整屏生成雨，不会退回 80×24。
- **非 TTY（stdout 是管道）**：不进 alternate screen、不隐藏光标，仍然输出带
  CUP 绝对定位的完整帧；首帧整屏覆盖写、之后只写变化格、从不清屏，经过
  `zlolcat` 之后画面完整。
  实测 `zmatrix -u 0 | zlolcat` 在 120×40 终端下写满 40 行、每行 120 列。

## 帧差分（damage tracking）

和 ncurses 的 `refresh()` 做的是同一件事，只是这里是自己的实现：

1. 每格维护「字符码 + 打包颜色」（`u16`：kind 2 位 + 前色 8 位 + 粗体 1 位），
   两块网格 `front`（已经画在屏幕上的）和 `back`（本帧目标）双缓冲互换。
2. 逐行扫描 `back`，跳过和 `front` 相同的格子；连续脏格合并成一段，
   每段只发一个 `\e[行;列H` 再跟一串字符。
3. 段之间如果只隔 ≤4 个干净格，就顺带重画（重画 1 个空格是 1 字节，
   而再发一次 CUP 要 7~9 字节）。
4. 颜色只在变化时发 SGR；**空格永远不发 SGR**（空格的颜色不可见，
   一个 `\e[0m` 是 4 字节，纯浪费）。
5. 整行没变 → 这一行完全不输出；整屏没变 → 这一帧 0 字节（暂停时就是这个效果）。
6. 首帧/resize 后 `front` 全是哨兵（`UNKNOWN`），于是每一格都算脏，
   自然退化成「整屏覆盖写、每行写到右边界」——不需要第二套代码。

只有 `--fade`（每格档位每帧都在变）和 `-r` 彩虹（每格颜色每帧重掷）会退化成
接近整屏重画 —— cmatrix 在这两种模式下同样是每格都脏。

单元测试里有一条专门守这个不变量：同一 seed 下跑两个矩阵，一个走帧差分、
另一个每帧 `forceFullRepaint()`，90 帧后把两边叠加出来的画面逐格比较，
字符必须完全相同、非空白格的前景色也必须相同。

## 与 cmatrix 2.0 的差异

**不绘制背景色。** 发行版里的 cmatrix 2.0 走的是
`init_pair(COLOR_X, COLOR_X, COLOR_BLACK)` 那一边，于是每一格都先下发
`\e[40m` 把背景刷黑，再叠绿色前景（24×80 一屏正好 6401 次）。在非纯黑主题的
终端里，这层自绘的黑色幕布和终端自身的底色对不上，看起来像一块灰幕。

zmatrix 只发前景色，从不发 `40-47`、`48;`、`100-107`，也不用反显/dim 模拟：

| 场景 | cmatrix 2.0 | zmatrix |
| --- | --- | --- |
| 每个格子 | `\e[40m` + `\e[32m` | 只有 `\e[32m` |
| 头部 | `\e[40m` + `\e[37m`（+`\e[1m`） | `\e[37m`（+`\e[1m`） |
| 终端底色 | 被覆盖成黑 | 透出来 |
| 管道模式 | — | 同样不带背景 |

前景色、白色头部、粗体四档、偶数列、密度、`-k` 变字比例全部照 cmatrix 行为。
需要检查时可以抓帧统计：输出里 `\e[4Xm` / `\e[48;` 的出现次数必须为 0
（单元测试里有一条专门守这个）。

## 与 cmatrix 原版的差异

已对齐（实测）：列密度（偶数列）、字符集区间、颜色档位（8 色 + 粗体四档）、
头部白色且位于雨柱最下端、新式/旧式两种滚动、`-k` 的变字比例、`-a` 的三档
速度、`-M` 居中三行、`-u` 的 10ms 单位、`!@#$%^&` 换色同时关彩虹、SIGWINCH 重建。

| 项目 | 处理 | 原因 |
| --- | --- | --- |
| 字节量 | 反而是原版的一半：750 B/帧 vs 1521 B/帧（80×24）、1172 vs 2215（120×40） | 两边都有 damage tracking。这里每帧只发脏格 + 空格不发 SGR，ncurses 的 diff 更保守（它不合并跨格段、每个属性变化都要重新定位） |
| `-u 0` 帧率 | 约 7200 fps（80µs 帧预算），原版约 2~5k fps | 原版 `napms(0)` 不睡，但 curses 每帧 diff+刷新自带 200µs 开销；我们不加预算就会跑到 3 万 fps，把终端打爆（见下） |
| 帧率 | `-u 4` 双方都是 25.2 fps；`-u 1` 时 zmatrix 98.5 / 原版 88.8 | 原版 `napms(u*10)` 之外还有 ncurses 每帧 diff+刷新开销；这里画完再 `poll` 等 `u*10` ms |
| `-c` 片假名 | 55 个码位、窄字符、偶数列 | 原版走 ncursesw，半角片假名在 pty 下会被当成宽字符（实测占满 80 列、夹杂黑底空格与 ACS 字符），无法也不该复刻 |
| `-x` X 模式 | 每字画两次模拟双宽 | 原版依赖 mtx.pcf 位图字体（码位 166..216 + `A_ALTCHARSET`），纯终端下无等价物 |
| `-t <tty>` | 未实现 | 需要自己 open 设备再 `newterm`，现代终端 + `TERM` 探测已覆盖 |
| `-f` | 接受但无作用 | 原版只用来 `setenv("TERM","linux")`，这里不做色深探测 |
| `-L` 锁定 | 未实现 | 非观感特性 |
| `-l` 语义 | 实现为「指定字符集」 | 原版是控制台字体开关；保留扩展用法并在帮助里注明 |
| `-s` 屏保 | 任意键退出，但不回推按键 | 原版用 `TIOCSTI` 把按键塞回终端；该 ioctl 在新内核上受限 |
| `-M` 宽度 | 按码位数而非字节数算宽度 | 原版用 `strlen`，UTF-8 消息会算宽 |
| `--fade` / `-m` / `-k` 键 / `c` 键 | 额外或调整 | `--fade` 是扩展；`-m` 与原版同名同义；原版用 `n` 关粗体，字符集循环改绑到 `c` |

```
        -u 1   -u 2   -u 4   -u 7   -u 10

```

- 非空列均值都低于峰值（80×24 峰值 40 = `cols/2`，120×40 峰值 60 = `cols/2`）：
  每根雨柱在两次下落之间会留一段 `spaces[]` 间隙，所以任一时刻只有 7~8 成的
  逻辑列有字符。这两列数字是 cmatrix 与 zmatrix 最直接的密度对照。
- 白色格/帧 ≈ 非空列数：每段雨柱恰好一个白色头部。偶尔一列里同时有两段雨
  （各自有头部），所以白色格数比非空列数略高 —— 原版同样如此。
- `-u 1` 时 zmatrix 更接近理想的 100fps：ncurses 每帧 diff + 刷新的固定开销
  让 cmatrix 掉到 88fps；`-u ≥ 2` 两者误差在 2% 以内。
- 字符格/连续率/头部位置在帧差分前后没有变化：差分只改变「往终端写什么」，
  不改变模拟。测试里用同一 seed 对跑（一个走差分、一个每帧整屏重画）逐格比较，
  90 帧后字符完全一致、非空白格前色完全一致。上表 345 vs 375 的差别来自随机
  种子与 3 秒窗口内雨柱的相位（同一 seed 下两边是逐格相同的）。
- 256 色/16 色不再混用：默认路径只发 `\e[32m` / `\e[37m`，不再出现
  「头部发 `1;97m`、拖尾发 `38;5;46m` 但粗体没关」的泄漏（修复前整屏尾色都带 `1;`）。
- `-k` 变字比例：cmatrix 11% / 修复前 45% / 修复后 12%（每帧变化的可见字符占比）。
- `-o`：修复前只是关掉渐隐（颜色仍 `38;5;46`，字符集最高到 `~`）；修复后出现
  原版特征 —— `|` 标记、白 `&` 头部、实心雨柱，密度 0.275 vs 原版 0.267。
- resize（80×24 → 100×30 → 60×18）：只重画到 58 列、18 行，全部落在偶数列，
  `\e[2J` 恰好 3 次（启动 + 两次重建），没有残留。
- 资源：RSS ≈ 0.7 MB；`-u 4` 时 CPU ≈ 0~2%，`-u 0` 从「满速空转 44%」降到 22%
  （帧预算让它把这 80µs 睡掉而不是空转）。
- `ZMATRIX_SEED=<n>` 可固定随机种子，便于逐格对比帧；`ZMATRIX_FORCE_TTY=1`
  用于没有 pty 的环境验证 alternate screen / 恢复序列。
